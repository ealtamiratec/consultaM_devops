Infraestructura como Código (IaC)
Terraform + Ansible

CI/CD funcional

Orquestación
Kubernetes en Docker Desktop

Observabilidad
Prometheus + Grafana

Resiliencia
Fallo inducido + recuperación

Métricas DORA en modo laboratorio

Todo ocurre localmente, pero simula un entorno real DevOps.

🧩 Paso 1: Preparar el entorno local
1.1 Requisitos mínimos

Instala en tu máquina:

Docker Desktop (con Kubernetes habilitado)

Git

Terraform

Ansible

kubectl

Helm

Cuenta GitHub

👉 Tip para novatos:
Docker Desktop → Settings → Kubernetes → Enable Kubernetes ✔️

🧠 Paso 3: La aplicación (dummy pero real)

Apache + PHP

☸️ Paso 5: Kubernetes (entorno de laboratorio)

Deployment de la app

Service tipo ClusterIP

🧱 Paso 6: Infraestructura como Código (IaC)
6.1 Terraform (infraestructura)

En local, Terraform no crea cloud real, pero declara el entorno:

Namespace Kubernetes

Recursos base

Variables reutilizables

👉 Esto demuestra mentalidad IaC, aunque sea local.

6.2 Ansible (configuración)

Ansible se usa para:

Inicializar configuraciones

Aplicar manifests

Instalar Helm charts (Prometheus/Grafana)

Terraform = qué existe
Ansible = cómo se configura

🔁 Paso 7: CI/CD con GitHub Actions
7.1 Flujo del pipeline

Cada git push ejecuta:

Checkout del código

Build de la imagen Docker

Test básico (lint o health)

Push imagen (local registry o Docker Hub)

Deploy a Kubernetes

Verificación de despliegue

👉 Esto es el corazón DevOps del laboratorio.

📊 Paso 8: Observabilidad
8.1 Prometheus

Recolecta:

CPU

Memoria

Estado de pods

Restart count

8.2 Grafana

Dashboard muestra:

Pods UP/DOWN

Uso de recursos

Tiempo de respuesta

👉 Incluye capturas de pantalla como evidencia.

💥 Paso 9: Prueba de resiliencia (obligatoria)

Elimina un pod manualmente:

kubectl delete pod <pod-name>


Observa:

Kubernetes crea otro pod

Prometheus registra el evento

Grafana muestra la caída y recuperación

📌 Esto valida MTTR y auto-healing.

📈 Paso 10: Métricas DORA (modo laboratorio)

Acláralo explícitamente en el informe:

“Las métricas DORA se obtienen en un entorno de laboratorio controlado, no en producción real.”

Cómo las mides:

Lead Time for Changes
⏱ Desde commit → pipeline exitoso (GitHub Actions)

Deployment Frequency
🔁 Número de despliegues durante el día de pruebas

Change Failure Rate
❌ Pipelines fallidos / total pipelines

MTTR
⏱ Desde fallo inducido → servicio restaurado
